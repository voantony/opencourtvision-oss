# labels/: event ground truth for `ocv eval`

One JSON file per video. Only synthetic or redistributable labels go in the repo. Never commit labels that
identify real players or private matches; keep those in your work dir and point `--labels` at it.

```json
{"video": "club_final.mp4", "fps": 30,
 "events": [
  {"type": "contact", "t": 12.345, "player": "P1",
   "label": {"position": "near_deuce", "shot_type": "serve", "direction": "T", "formation": "i_formation", "outcome": "in", "hand": "right"}},
  {"type": "bounce", "t": 12.91},
  {"type": "point_end", "t": 19.2}]}
```

- `type`: `contact` and `bounce` are matched at ±80 ms; every other type (`point_start`, `point_end`, `callout`, ...) at ±150 ms.
- `label` fields and allowed values: see `opencourtvision/labels/schema.py` (court position near/far × deuce/ad; side;
  shot type serve, second_serve, return, volley, lob, smash, swing; direction T/body/wide for serves, cross_court,
  down_the_line, inside_in, inside_out otherwise; formation conventional, i_formation, australian, non_serve; outcome in/win/error).
  `opencourtvision.labels.validate` / `validate_rally` check the handedness and rally rules.
- Predictions use the same format plus `confidence`, `evidence` and `verified` (see `opencourtvision/events.py`).

`synthetic_doubles.json` is generated by `opencourtvision.labels.synthetic.ground_truth(n_rallies=4, seed=7)`, and
`examples/pred_synthetic_doubles.json` is a corrupted copy, so `ocv eval --pred examples/pred_synthetic_doubles.json --labels labels/synthetic_doubles.json` works out of the box.
